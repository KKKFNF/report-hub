1. 설계 원칙 — 왜 이렇게 만들었나

구루 원칙을 에이전트로 만든 공개 사례와 백테스트 검증 논문을 먼저 검토한 결과는 다음 한 줄로 요약됩니다. 정량 룰이 수익의 몸통이고, LLM 페르소나는 알파 원천이 아니라 정성 필터·설명 레이어로 쓸 때만 방어 가능하다.

  • 룰은 결정론적: 같은 입력이면 같은 출력. 가중치·임계값은 config.py 한 곳에만 있고, 바꾸면 버전을 올려 블록 스냅샷 줄에 남깁니다(GuruAgents 가 쓴 '결정론적 파이프라인' 방식).
  • LLM 은 점수에 섞지 않음: 버핏·멍거·드러켄밀러 3인에만 정성 필터를 붙이고 결과는 별도 열에 표기합니다. 20년·100+종목(FINSABER)·지식컷오프 이후 구간(Profit Mirage)에서 LLM 직접 판단의 우위가 사라진다는 결과를 반영한 것입니다.
  • 누수 방지: LLM 입력은 종목명·코드·절대연도를 지우고 매출=100·총자산=100 지수로 바꿉니다(Kim·Muhn·Nikolaev 의 익명화 재무제표 방식). LLM 이 '외운 미래'로 답하는 것을 줄이기 위함입니다.
  • 의견 전용: v1 은 결정카드(판정·진입·손절·목표)를 절대 바꾸지 않습니다. 원장(ledger)에서 사후 수익률 엣지가 확인될 때만 판정 입력으로 승격합니다(8절).
  • 검산 가능: 모든 근거 문장에 사용한 숫자를 그대로 적고, 데이터 스냅샷(DART 접수번호·KIS 시각·룰/프롬프트 버전·모델)을 블록 끝에 남깁니다.
참고한 근거: GuruAgents(CIKM 2025, 프롬프트에 스코어링 수식 공개) · FINSABER(KDD 2026, 20년·100+종목 백테스트에서 LLM 전략 열위) · Profit Mirage(2025, 컷오프 이후 샤프 51~62% 감소) · Buffett's Alpha(AQR, 버핏 알파 = 저베타·퀄리티 + 1.7× 레버리지) · Validea 구루 모델 22년 트랙레코드(룰 기반 소폭 초과). 상세 분석은 별도 리서치 노트.

  • 마커 규칙은 기존 <!-- hub:enrich:begin:코드 --> 와 같은 방식입니다. 테마 리포트(종목별 카드 분리)는 종목마다 블록 1개.
  • 결정카드가 "리포트 맨 끝"이라는 허브 파서 전제를 지키기 위해 블록은 항상 카드 앞에 들어갑니다. 블록 본문에 📋 결정카드 문자열을 쓰지 않아 카드 파서·품질점수와 충돌하지 않습니다.
  • 재실행(가격 갱신·데이터 갱신) 시 같은 코드의 블록만 통째로 교체되므로 중복이 생기지 않습니다. 리포트 본문은 한 글자도 바뀌지 않습니다.
  • 허브 빌더의 md→html 변환기가 raw HTML 을 이스케이프하므로 블록은 순수 Markdown(제목·표·목록·기울임)만 씁니다.

4. 룰 레이어 수식 (코드와 동일)

공통: s(x; lo, hi) = clip((x − lo)/(hi − lo), 0, 1), lo > hi 이면 '낮을수록 좋음'으로 자동 반전. 점수 = Σ(가중치×구성요소) ÷ Σ(가용 가중치) + 보너스/페널티, 0~1 로 클립. 가용 가중치 합이 50% 미만이면 점수를 내지 않고 '데이터부족'. 판정: 점수 ≥ 0.65 적합 · ≥ 0.45 보류 · 미만 부적합(그레이엄·피오트로스키는 자체 임계값).

4.5 그린블라트 마법공식

  • 이익수익률 = 영업이익(TTM) / EV, EV = 시총 + 총차입금 − 현금성자산
  • 자본수익률 = 영업이익(TTM) / (순운전자본 + 순유형자산)
  • 적격: 영업이익 > 0, EV > 0, 투하자본 > 0, 금융·지주 제외 (금융·지주는 '해당없음')
  • 유니버스 통계 파일이 있으면 Score = 1 − (rank_EY + rank_ROC − 2)/(2N − 2)
  • 유니버스 없을 때: 0.5·s(EY; 0%→0, 15%→1) + 0.5·s(ROC; 0→0, 40%→1)
  • 안전 페널티: 이자보상배율 < 3 -0.03, 총차입금/자본 > 1.0 -0.03

드러켄밀러 원칙(변화·유동성·비대칭·집중)은 재무제표 스크린으로 환원되지 않습니다. 그래서 이 행은 '이 종목이 좋은가'가 아니라 '지금 이 베팅 구조가 드러켄밀러 식으로 유리한 상황인가'를 점수화합니다. 레짐 파일이 없으면 중립 0.5 로 두고 그 사실을 블록에 적습니다.

5. LLM 정성 필터

  • 대상: buffett, munger, druckenmiller (그레이엄·피오트로스키·그린블라트는 룰만). temperature 0.0, 기본 모델 claude-sonnet-5-5, 최대 700 토큰.
  • 익명화:
    · 종목명·종목코드 → A사 (리포트 내 다른 종목은 B사·C사…)
    · 절대 연도 → t-0/t-1/t-2 (리포트 발행연도 기준), 분기표기 1Q26 → 1Q(t-0)
    · 손익계산서 항목은 매출=100 기준 지수, 재무상태표 항목은 총자산=100 기준 지수로 변환
    · 절대 금액(억원)·시총·주가는 전달하지 않음(기업 식별 방지)
  • 프롬프트 핵심 명령: "회사를 추정하지 말고 제시된 사실만으로 판단, 없는 사실은 '불명', 출력은 JSON 하나". 프롬프트 원문은 guru/prompts/*.md.
  • 출력 스키마(키 고정): 버핏 moat, moat_evidence, capital_allocation, accounting_quality_flags, management_red_flags, verdict, confidence, one_line · 멍거 how_it_fails, predictability, incentive_alignment, too_hard_pile, verdict, confidence, one_line · 드러켄밀러 change_thesis, what_must_be_true, asymmetry, verdict, confidence, one_line. 스키마가 깨지면 그 셀은 'LLM 오류'로 표기하고 룰 결과는 그대로 둡니다.
  • 캐시: (프롬프트 버전·페르소나·모델·패킷 해시) → ~/.guru/cache/llm. 같은 입력은 다시 호출하지 않습니다.
  • 백엔드: GURU_LLM_BACKEND=anthropic(API 키) 또는 command(OpenClaw/Claude CLI 등 셸 명령에 stdin 으로 프롬프트 전달) 또는 none.
LLM 셀은 룰 점수·합의 수에 전혀 반영되지 않습니다. "해자·자본배분·회계품질·실패경로·변화 가설"처럼 숫자로 환원되지 않는 항목을 사람이 읽기 위한 보조 의견입니다.

6. 합의 · 결정카드 관계 · 반증

  • 합의 = 6구루 중 '적합' 수. 버킷: ≥4 hi · 2~3 mid · 0~1 lo. 평균은 점수가 산출된 구루만의 평균이며 '산출 n/6'을 함께 표기합니다(데이터부족이 많으면 평균이 과대해 보일 수 있어서).
  • 요약문: 가치·품질 축(버핏·멍거·그레이엄·피오트로스키·그린블라트) 적합 ≥3 → '가치·품질 적합', 1~2 → '부분 적합', 0 → '미달' + 드러켄밀러 판정을 '상황 우호/중립/비우호'로 붙입니다.
  • 결정카드 관계(카드는 바꾸지 않고 비교만): 카드 매수 & 적합 ≤1 → 상충 · 카드 관심/관망 & 적합 ≥4 → 우호 · 카드 매수 & 적합 ≥3 → 보강 · 데이터부족 ≥4 → 비교 보류 · 그 외 중립.
  • 구루 레이어 반증: '적합'으로 판정된 구루마다 철회 조건을 자동 생성합니다(버핏: ROE<8% 또는 FCF≤0, 멍거: 분기 영업적자·감사의견 비적정, 그레이엄: 유동비율<1.5 또는 PER×PBR>22.5, 피오트로스키: F<4, 그린블라트: 영업적자 또는 하위 50%, 드러켄밀러: MA200 하향·외인/기관 합산 순매도 전환).

7. 허브 표시(후처리)

python -m guru postprocess REPO 는 빌더(춘식이)가 index.html 과 리포트 html 을 만든 뒤에 실행합니다. 빌더 코드는 건드리지 않습니다.

  • index 카드: data-guru="hi|mid|lo" data-gurun="N" 속성 + 배지 🧭 구루 N/6(툴팁에 구루별 판정·점수·카드 관계). 기존 필터 JS(data-키 == 값)를 그대로 이용해 칩 🧭 구루 합의 4+, 🧭 구루 2~3 을 추가합니다.
  • 내비에 🧭 투자구루 판단(이 페이지) 링크, 상단 stats 에 '구루 평가 N'.
  • 리포트 html: 빌더가 md 를 재렌더해 블록이 이미 있으면 건너뛰고, 없으면 같은 블록을 html 로 변환해 결정카드 앞에 삽입(<!--guru:html:begin:코드--> 마커로 멱등).
  • 카드와 리포트 파일명(stem)·코드가 정확히 일치할 때만 배지를 붙입니다. 종목의 최신 리포트에 블록이 없으면(예: 10/14 리포트가 최신인데 10/12 리포트에만 블록) 배지를 붙이지 않습니다 — 오래된 의견을 최신 카드에 달지 않기 위함.
  • 원장 연계: python -m guru collect REPO --csv guru_ledger.csv 가 (리포트, 날짜, 코드, 합의, 버킷, 구루별 판정/점수) CSV 를 내보냅니다. 원장 빌더가 날짜·코드로 조인해 D+5/D+20 표에 '구루 합의 hi/mid/lo' 행을 추가하면 됩니다.

9. 한계·주의

  • 계정 매칭: DART 의 '-표준계정코드 미사용-' 계정은 이름 정규식으로 잡습니다. 첫 도입 시 종목 몇 개를 guru fundamentals --code 로 뽑아 DART 원문과 대조하세요. 틀리면 ~/.guru/fundamentals/코드.json 을 손으로 고치면 그 파일이 우선 적용됩니다.
  • 이자비용이 분리 공시되지 않으면 금융비용(외환손실 포함)을 써서 이자보상배율이 과소평가될 수 있습니다(블록 근거에 표기).
  • TTM 합성은 손익·현금흐름만 하고 재무상태표는 최신 분기말을 씁니다. 분기 보고서에 없는 항목(배당·자사주 등)은 TTM 에서 None 이 되어 해당 구성요소가 빠집니다.
  • 익명화는 불완전합니다. 제품명·업종 서술로 LLM 이 회사를 알아볼 수 있습니다. 그래서 LLM 셀은 점수에 넣지 않고, 프롬프트로 '추정 금지'를 명령하며, 원장 검증에서는 룰 점수만 봅니다.
  • 금융·지주: 그린블라트 '해당없음', 버핏·멍거는 지주 페널티 플래그만. 은행·보험은 별도 프레임이 필요하며 v1 에서는 데이터부족으로 나올 수 있습니다.
  • command 백엔드(CLI 경유)는 temperature 를 보장하지 못해 LLM 셀이 재실행 시 달라질 수 있습니다. 캐시가 같은 입력의 재호출은 막습니다.
  • 레짐 파일이 없으면 드러켄밀러 레짐 점수는 중립 0.5 입니다. 블록에 그 사실이 적히므로 '레짐 2026-..'이 없는 블록은 상황 점수를 할인해서 읽으세요.
  • 이 블록은 투자 권유가 아니며, 허브의 결정카드와 마찬가지로 사후 엣지 검증 전까지는 아이디어 점검용입니다.

12. 검산 예시 — 버핏 점수

A사 구성요소: ROE 평균 10.5% → s(8%,20%) = 0.21 · ROE 최저 9.6% → 0.46 · FCF 수익률 7.0% → 0.88 · OPM 안정성 0.93 · 이자보상 34.7배 → 1.00 · 밸류(PER 12.8, PBR 1.47) → 0.57

가중합 = 0.25×0.21 + 0.15×0.46 + 0.20×0.88 + 0.15×0.93 + 0.10×1.00 + 0.15×0.57 = 0.621 → 보너스/페널티 +0.00 → 점수 0.62 → 보류(임계 0.65/0.45).

피오트로스키: TTM(2Q26) vs TTM-1Y(2Q25) 9개 신호 전부 통과(자산회전율 0.785→0.827 증가 포함) → 9/9. 그린블라트: EY = 520/(5,000+370−720)= 11.2%, ROC = 520/((2,450−720)−(1,050−110)+1,850)= 19.7%.
